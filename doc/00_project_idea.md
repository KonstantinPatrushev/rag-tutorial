# Идея проекта

**Учебный, но современный RAG** — пример, на котором видно, как устроен
полный pipeline retrieval-augmented generation и как довести его качество до
SOTA-уровня: от сырых данных до ответа с источниками и измеримыми метриками.

## Проблема

RAG часто воспринимают как «промпт к ChatGPT», хотя это **цепочка шагов**:
данные → чанки → индекс → поиск → (фьюжн → reranking) → ответ.

Без рабочего примера непонятно, где именно на каждом этапе теряется качество и
как его измерить.

## Цель

Собрать проект, который:

- проходит весь pipeline от сырых данных до ответа **с источниками**;
- использует **современные подходы**: hybrid search (dense + BM25), RRF,
  cross-encoder reranking, LLM-генерацию с цитатами и grounded-отказом;
- **измеряет** качество retrieval на golden-set (recall@k, hit@k, MRR);
- запускается локально и воспроизводимо;
- документирует ход разработки, чтобы повторить логику на своих данных.

## Для кого

Студенты и разработчики, которые учатся строить RAG и хотят сразу видеть не
наивный, а близкий к продакшену вариант.

## Зачем RAG

Обычная LLM не знает ваших документов и может выдумать ответ. RAG сначала
**ищет** релевантные фрагменты, потом **генерирует** ответ по ним:

```
вопрос → hybrid retrieval → RRF → rerank → контекст + вопрос → ответ со ссылками [n]
```

## Данные

**HuggingFace SberQuAD** — русскоязычный QA-датасет на абзацах Википедии.
Почему подходит:

- открытые данные, легко скачать через `datasets`;
- абзацы Википедии дают разнотемный корпус (1000+ записей);
- встроенные пары **вопрос → правильный контекст** дают честный golden-set
  для метрик retrieval — это редкое и ценное свойство для учебного проекта.

## Результат

Streamlit-приложение: задаёшь вопрос на русском — система находит фрагменты
(показывая вклад dense/BM25/RRF/rerank), формирует ответ с цитатами и явно
отказывается, если в базе нет ответа.

## Критерий успеха

Студент может объяснить:

1. Зачем каждый шаг pipeline и чем hybrid лучше одиночного поиска.
2. Что делает RRF и reranking и почему это улучшает качество.
3. Как измерить качество retrieval (recall@k, MRR) и доказать прирост.
4. Почему ответ без источников и без порога отказа ненадёжен.
