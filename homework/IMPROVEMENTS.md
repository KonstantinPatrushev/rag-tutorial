# Улучшения MVP: план и реализация

Базовый MVP репозитория-образца — TF-IDF + extractive demo-ответ. Ниже —
направления улучшений, **что реализовано** в этой работе и как проверено, что
стало лучше.

Легенда: ✅ реализовано · 📋 описано

---

## ✅ 1) Semantic-эмбеддинги вместо TF-IDF

- **Зачем кейсу:** вопросы к Википедии часто перефразированы, без общих слов с
  текстом — TF-IDF их не находит, нужен поиск по смыслу.
- **Файлы:** `app/embedder.py` (sentence-transformers `multilingual-e5-small`,
  префиксы `query:`/`passage:`, L2-норма), `scripts/build_index.py`.
- **Как проверено:** тест `tests/test_retrieval.py::test_semantic_match_finds_right_doc`
  — запрос-перефразировка без точных слов находит правильный документ; рост
  метрик на golden-set (см. README).

## ✅ 2) Hybrid search (dense + BM25) + RRF

- **Зачем:** dense ловит смысл, BM25 — точные термины/имена/числа. Вместе —
  устойчивее.
- **Файлы:** `app/index.py` (FAISS + BM25), `app/retriever.py`
  (`reciprocal_rank_fusion`).
- **Как проверено:** `tests/test_fusion.py`; в выдаче видны dense-ранг и
  BM25-ранг каждого источника.

## ✅ 3) Cross-encoder reranking

- **Зачем:** bi-encoder кодирует запрос и документ раздельно (грубо);
  cross-encoder оценивает пару напрямую — точнее. Паттерн retrieve-then-rerank.
- **Файлы:** `app/reranker.py` (`DiTy/cross-encoder-russian-msmarco`), интеграция в
  `app/retriever.py`.
- **Как проверено:** `scripts/evaluate.py` сравнивает `hybrid+RRF` и
  `hybrid+RRF+rerank`: на golden-set reranking поднимает hit@3 0.96→0.99 и
  hit@5 0.97→0.99 (числа в README) и, главное, даёт **калиброванный score
  релевантности**, на котором строится корректный отказ для вопросов вне корпуса.
  Откат на RRF, если модель недоступна.

## ✅ 4) Векторная база / индекс

- **Зачем:** быстрый поиск ближайших по большому корпусу.
- **Файлы:** `app/index.py` — **FAISS** `IndexFlatIP` (cosine на нормированных
  векторах), сохранение/загрузка артефактов.
- **Как проверено:** индекс собирается `build_index.py`, загрузка проверяет
  синхронность с `chunks.jsonl`.

## ✅ 5) Подключение LLM + grounded-отказ

- **Зачем:** связный ответ на естественном языке, но **только по контексту**,
  с цитатами и отказом при отсутствии данных.
- **Файлы:** `app/llm.py` (OpenAI-совместимый клиент), `app/prompts.py`
  (правила + формат `[n]`), `app/generator.py` (порог релевантности → отказ,
  extractive-fallback без ключа).
- **Как проверено:** `tests/test_generator.py` (цитаты, отказ по порогу,
  пустой вопрос); `scripts/check_generator.py` (3 ответа + 1 отказ).

## ✅ 6) Оценка качества (Eval)

- **Зачем:** доказать, что улучшения реально работают, а не «на глаз».
- **Файлы:** `scripts/evaluate.py` (recall@k / hit@k / MRR на golden-set из
  SberQuAD), `tests/test_eval.py`.
- **Как проверено:** метрики воспроизводимы; отчёт `data/index/eval_report.json`.

## ✅ 7) Улучшенный UI

- **Файлы:** `app/main.py` — настройки (top-k, переключатель reranker), для
  каждого источника видны вклад dense/BM25/RRF/rerank, режим генерации.

---

## 📋 Дальнейшие направления (не реализованы)

- **Векторная БД с обновлением** (Qdrant/Chroma) вместо файлов FAISS — для
  инкрементальных апдейтов корпуса.
- **Semantic chunking** по эмбеддингам границ вместо предложенческого.
- **RAGAS-метрики генерации** (faithfulness, answer relevancy) поверх
  retrieval-метрик.
- **Кэш эмбеддингов запросов** и батч-режим reranker для ускорения.
